# 真实门店菜单策略

日期：2026-10-30  
决策：**分层策略**。

## 1. 决策

真实门店分两层：

1. **有菜单的门店**：参与外食推荐。
2. **无菜单的真实 POI**：只用于地图、后台统计和大屏，不进入菜品推荐。

不做“给 7,664 家门店批量生成假菜单”。

## 2. 当前覆盖

| 类型 | 数量 | 是否推荐 |
|---|---:|---|
| 有菜单门店 | 40 | 是 |
| 其中思源 fixture | 20 | 是 |
| 其中建大 fixture | 20 | 是 |
| 真实高德 POI | 7,264 | 否 |
| 合成食堂 POI | 400 | 否 |
| 门店合计 | 7,704 | — |
| 外食菜品 | 120 | — |

说明：

- 40 家 fixture 门店各带 3 道外食菜品。
- 思源、建大各 60 道。
- 真实门店没有菜单数据，因此不会出现在推荐里。
- 推荐查询本身是“菜品驱动”的：没有菜品的门店自然被排除，不需要额外伪造菜单。

## 3. 数据规则

- 有菜单门店：`restaurants` 中存在关联 `dishes_and_recipes.restaurant_id`。
- 无菜单门店：没有任何关联菜品。
- 真实 POI 的 `source_dataset` 为 `amap_place_around_20261025`。
- 合成食堂的 `source_dataset` 为 `synthetic_canteen_v1`。
- fixture 门店当前 `source_dataset=NULL`，通过“有菜品”识别。
- 后续如果补菜单，必须明确来源：
  - `menu_source=real`：真实授权菜单
  - `menu_source=curated`：人工整理菜单
  - `menu_source=synthetic`：合成菜单，必须显式标记，不能当真实菜单宣传

## 4. 推荐行为

- 外食推荐只从有菜品的门店出候选。
- 无菜单真实门店不参与 `/recommend/single`、房间候选、外食统计推荐口径。
- 地图、POI 数量、后台大屏仍使用全量 7,704 家门店。
- 不因为“校区门店很多”就假设有菜单。

## 5. 为什么不做全量合成菜单

- 7,664 家 × 3–5 道会产生 2–4 万条假菜单。
- 菜名、价格、菜系都无法对应真实门店。
- 答辩时无法解释“为什么每家店都有菜单”。
- 会把推荐结果变成合成数据自娱自乐，降低可信度。

## 6. 后续扩展

如果以后拿到真实菜单：

1. 按门店导入菜单。
2. 补 8 维特征向量。
3. 标记 `menu_source` 和 `source_dataset`。
4. 先小批量试跑推荐，再扩大覆盖。
5. 没有菜单的门店继续只做 POI。
