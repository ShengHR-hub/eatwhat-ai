# V5 极简设计决策

日期：2026-10-29
状态：设计基线已确认，主项目 Vue 迁移按页面分批进行。  
适用范围：移动端 `/m/*` 与 APK；PC 后台沿用现有后台视觉，不在本轮重做。

## 1. 视觉方向

- 关键词：极简、纸感、青黛水彩、Apple 玻璃、信息克制。
- 首页从“大图卡片”改为“决策台”：场景、雷达、理由、一个主操作。
- 所有功能不堆在首屏；模式、预算、状态、筛选、算法、背景图统一进抽屉。
- 不生成假菜照；没有图片时用雷达和文字成立。
- 底部导航为悬浮玻璃 Dock，五项：首页 / 足迹 / 冰箱 / 房间 / 我的。

## 2. 颜色令牌

以“青鸾 → 菘蓝 → 青黛 → 绀蝶”为基础：

默认使用“燕麦暖食”，深色“青黛水彩”保留为可选主题。

| 角色 | 默认燕麦 | 青黛可选 |
|---|---|---|
| 背景 | `#F4F1EA` | `#2C2F3B` |
| 主文字 | `#241E18` | `#F0F3F6` |
| 次文字 | `#6E6256` | `#B4C0C9` |
| 弱文字 | `#A39A8C` | `#7E8B9C` |
| 强调 | `#B85C2E` | `#9AA7B1` |
| 导航底 | 玻璃暖白 | `#353846` |
| 卡片/暗部 | `#FFFDF8` | `#45465E` |

颜色必须走令牌，不在组件里散写裸 hex。调色台 `design/color-lab/index.html` 是唯一实验入口。

## 3. 背景与玻璃

- 纸感颗粒：`assets/paper-grain.png`，低透明度、`multiply`。
- 水彩晕染：`assets/watercolor-ink.png`，青鸾/菘蓝/青黛/绀蝶，预渲染透明纹理。
- 抽屉/导航：真实 `backdrop-filter`，深色玻璃 alpha 约 0.42–0.66，模糊 28–52px。
- 禁止：全屏动态渐变、彩色 mesh、霓虹光晕、整页噪点动画。

## 4. 首页

- 顶部：问候、天气、模式入口、算法入口。
- 主体：一张大雷达 + 菜名 + 推荐理由 + 主按钮。
- 雷达：菜品八维风味；匹配度单独显示。
- 背景图：用户可上传；自动算平均亮度，选择浅色/深色文字；遮罩强度可调。
- 主按钮：毛玻璃高对比，不跟强调色走。
- 抽屉：模式、预算、状态、筛选、算法沙盒、背景图、快捷入口。

## 5. 足迹

- 主视图是时间线：今天 / 昨天 / 周一，每条记录含时间、菜名、地点、价格、模式、冷却状态。
- 周报不占主屏，放右上角“本周周报 →”抽屉。
- 周报包含：本周概览、一周节奏、预算执行、口味构成、下周建议。

## 6. 冰箱

- 主视图：先用临期 → 全部食材 → 今晚能做什么 → 生成买菜清单。
- 拍照入库：相机抽屉 → 云端识别 → 识别框 → 用户确认 → 入库。
- 识别结果必须可编辑：名称、数量、保质期、勾选。
- 低置信度默认不勾选；不能自动写入。
- 离线 YOLO 暂缓；第一版接云端视觉模型。
- 入库接口：现有 `POST /fridge/{user_id}` 可逐条写入；建议新增批量 `scan-import`，按名称去重并记录来源/置信度。

## 7. 房间

### 7.1 等待

- 房间码、二维码、成员到齐状态、开始划卡、三步规则。
- 同校区限制；跨校区不能拼桌。

### 7.2 划卡

- 15 秒倒计时、成员进度、菜品雷达。
- 雷达单图双线：
  - 深色线：菜品八维风味。
  - 橙色线：个人五维匹配。
  - 橙线独立缩放，右下角注释说明，不与八轴一一对应。
- 卡片内容随房间模式变化：
  - 外食：门店、距离、预算、等待时间。
  - 下厨：冰箱库存、厨具、时间、清库存。
- 四个动作：跳过 / 不吃 / 想吃 / 超想吃。

### 7.3 揭晓

- 赢家、群组满意度、平均满意度、最低成员、被否决候选。
- 每个成员对赢家的接受度。
- 解释“为什么是它”：不是最高平均分，而是最低成员满意度最高。
- 否决候选单列，不能与赢家否决混为一谈。

## 8. 我的

- 资料卡：头像、昵称、人设、预算、忌口。
- 饮食基因：八维雷达、预算、忌口、偏好标签。
- 干饭成就：连续不超预算、新菜尝试、按时吃饭。
- 红黑榜：红榜、黑榜菜品、黑榜门店。
- 演示角色切换抽屉：小赵 / 阿明 / 小王 / 小周，切换后资料与雷达实时变化。
- 外观与设置：背景图与配色、通知、隐私、关于。

## 9. 数据与 AI 边界

- 菜品图不是必需资产；6,400 道合成菜统一用雷达/文字展示。
- 云端视觉模型负责食材识别，用户确认负责数据正确性。
- 离线 YOLO 后续开发；如做，只做 20–30 类高频食材，菜谱库只提供类别表与同义词，不能生成检测框。
- 所有识别结果必须经过“确认入库”，不直接写库。
- 图片默认不长期保存，处理完即丢弃。
- 天气必须是实时数据：定位 → `/api/v1/context/weather` → 高德天气；定位失败回退校区中心点；缓存 10–15 分钟；失败显示明确降级，不能伪造 18°。设计页里的 18° 小雨只是静态占位。
- 前端不直接连接 SQLite；所有数据通过 `/api/v1` 接口，后端负责读写数据库。
- 背景图在静态设计页存 localStorage；迁移 Vue 后优先存用户偏好接口，接口未就绪时本地缓存兜底。

## 9.1 前端完成后的对接顺序

1. Vue 页面迁移完成，交互和空态稳定。
2. 接现有 API：用户、推荐、打卡、冰箱、房间、统计。
3. 补新接口：背景偏好、批量识别入库、房间逐用户匹配分。
4. 接实时天气与定位，保留失败降级。
5. 全量回归、真机 APK、冻结。
