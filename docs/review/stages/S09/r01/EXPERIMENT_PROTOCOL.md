## 3. 仿真数据写入位置

当前事实：PC01/r04 的仿真写在隔离库（`docs/review/stages/PC01/r04/data/`），演示库 `group_rooms=0, room_votes=0`。若 stats 只读 `backend/eatwhat.db`，大屏将看不到 24,000/40,000（D20）。

**本协议不替用户决定**。两种合法方案：

1. **主库写入**：S12/S13 将仿真用户/日志/房间/票写入 stats 读取的主库；必须能区分演示角色与仿真角色，并说明大屏是否展示全部。
2. **独立实验库**：S12/S13 写独立 SQLite，stats/大屏明确指向该库；演示库保持干净。

无论哪种，S13 的 `dataset_fingerprint` 必须指向实际被查询的库；不能“实验写 A、大屏读 B”。

## 4. 实验一：防腻衰减 vs 无衰减

### 4.1 对照定义

- **ours**：生产 `recommend_single()`，λ=0.5，查询时钟=餐次时间（可见近 14 天历史）。
- **baseline_no_decay**：同一个生产函数、同一库、同一人设、同一预算/天气/气泡；只把查询时钟推到 `LOOKBACK_DAYS+1` 天之后，使 14 天窗口内无历史，`W_decay=1.0`。
- 这不是“λ=0 公式替换”，也不是完整产品意义的“全新用户”；论文只能称“保持其余输入一致的无历史衰减基线”。
- 两臂不共享后续历史（各自从各自的选择演化），但共享初始人设、目录、预算、天气、随机种子。
- 若以后 `now` 参与天气/库存/预算等时效逻辑，必须重审该等价性。

### 4.2 重复率定义（待确认 D22）

当前实现（建议沿用）：

```text
duplication_rate(d) =
  截至第 d 天，所有用户「当前餐菜系 == 同一用户上一餐菜系」的次数
  ÷ 截至第 d 天，所有用户已记录的有效餐次
```

- 每人第一餐：计入分母，但没有上一餐，**不算重复**。
- `no_candidate`/跳过的餐次：不写入 eating_logs、不计入分母；必须在明细中计数。
- 同一天午餐→晚餐、跨天晚餐→次日午餐都算相邻；以用户为边界，不跨用户。
- `d` 是累计第 d 天，不是“第 d 天单日率”。
- 当前默认 seed 的 d14 为 `0.0091 / 0.2927`；备选“相邻转移为分母”口径给出 `0.0094 / 0.3035`（r02 报告）。两种不能混写，需用户选一。

### 4.3 输出

- 14 个 `days` 点（1..14），两条等长曲线；`d14` 单独报告。
- 记录每臂计划/实际/跳过餐次、每日分子分母（可复算）。
- 不挑选有利种子；seed 7 作为敏感性结果保留，即使不利。

## 5. 实验二：群组策略对照

### 5.1 三策略

在同一房间、同一成员、同一 10 张卡、同一票矩阵上比较：

| 策略 | 定义 |
|---|---|
| `mixed_omega_0.5` | 生产共识，ω=0.5 |
| `average_omega_1.0` | 纯均值，ω=1.0 |
| `random` | 从该房 10 张卡中随机抽 1 张；允许抽到被否决菜；不替它做 veto 过滤 |

### 5.2 个体与群组分数

```text
R[u,i]      = 0.4 * prior_score[u,i] + 0.6 * swipe_score
swipe_score = SUPER_LIKE 120 / LIKE 100 / PASS 40
VETO        = 0（计入四人集合，同时 Mask_veto(i)=0）
TIMEOUT     = 60（未投票/缺席；计入四人集合，不按 VETO）
G_score(i)  = Mask_veto(i) * (ω * mean(R[:,i]) + (1-ω) * min(R[:,i]))
```

- 个体 R 保留**原始值**，不在个体层封顶；SUPER_LIKE + 高 prior 可超过 100（最大 112）。
- 柱图是展示统计：四人 mean/min 计算后统一 `min(100, ·)`；最低值也要封顶（全员 >100 时可为 100）。
- 生产共识内部把 VETO 排除在 `satisfaction_values` 之外，这是排序实现；实验统计必须从 `members` 取全体四人，不能直接拿报告 `mean_satisfaction/least_misery`。

### 5.3 全否决与无共识

- 任意 VETO → 菜品 `masked_by_veto=true`，不得胜出。
- 全部候选被否决 → `has_consensus=false`，无赢家。
- 柱图对无共识房：建议均值/最低记为 0/0，**并单独报告 `no_consensus_rooms`**；不得静默剔除。若用户选择剔除，必须同时报告剔除数，不能只报好看的值。

### 5.4 random baseline 重复次数（待确认 D21）

建议 `R=30`：

- 第 r 次用 `random.Random(seed + 1 + r)` 抽签，r=0 与当前单次实现一致。
- 每个 repeat 先算 1,000 房的平均/最低，再对 30 次求均值；`params.random_repeats` 保存每次结果、均值、标准差与 95% bootstrap 区间。
- 四键 `group_satisfaction_bars` 仍只放 3 个策略的均值，不塞 30 组原始值；原始值进 `params`，避免破坏 SSOT 四键。
- 若用户要求 R=1，必须说明方差大、不能把单次差异当稳定结论。

### 5.5 缺席实验

- 独立 200 房、5% 不投票；TIMEOUT=60；结果只进 `params.absence`，不进四键、不混入主规模柱状。
- 主规模必须是满票：1,000 房 ×4 人×10 卡 = 40,000 张合法票；每房 40 张、唯一 `(user_id,dish_id)`。
- 超时/缺席不是“补票”；不得复制票或塞 TIMEOUT 凑 40,000。

## 6. 展示值与原始分

| 项 | 规则 |
|---|---|
| 单人排序 | 用原始 `total_score`；展示 `min(100, raw)` |
| 雷达五维 | 各分项 0–100，与总分封顶无关 |
| 群组个体 R | 原始值，不个体封顶 |
| 群组柱图 | 四人 mean/min 后统一 `min(100, ·)` |
| `SUPER_LIKE=120` | 保留；R 可 >100；不得改权重来压到 100 |
| random 抽到 VETO 菜 | 0 分进入四人集合；最低值可为 0 |

## 7. 结果统计方式

- 主要报告：每策略房间级均值的均值、最低值的均值、n、无共识房数、VETO 票数、缺席票数。
- 建议补充：房间级均值的 95% bootstrap CI（10,000 次重采样、固定种子）；不做显著性“证明”，不把很小的差异说成显著优势。
- 不隐藏不利种子/参数；seed 7 与默认 seed 并列报告。
- 不把合成人设实验写成真实用户实验；论文必须写“200 虚拟人设、rank 票型、固定超时/噪声”的模型假设。
- 不把无衰减基线写成竞品或完整冷启动；不把 d14 `.0091` 与旧模型 `.1696` 当作同一受控实验的提升。

## 8. 随机性与可复现

- 单人臂：`random.Random(seed)`；两臂各自从同一初始状态开始。
- 群组：`random.Random(seed)` 选成员/模式；`random.Random(seed+1)` 供 random 策略抽签；rank 票型噪声使用同一 RNG。
- 输出目录必须带 run 标识；不得覆盖旧证据（PC01 已加 `--data-dir`）。
- 记录：seed、λ、ω、输入指纹、代码 SHA、起止时间、每臂计划/实际/跳过、房间数/票数、无共识数、VETO 分布。
- 同输入同种子必须可复算；若不能，先修复现性再谈结果。
