## 五个开发组

### G1：多人交互与移动端完整回归（S07 + S08）

依次补齐多人真实交互、邀请/扫码、拖拽划卡、双身份和四身份流程、超时/全否决、断线重连、刷新恢复、揭晓；然后在同一代码版本完成移动端总回归、颜色/玻璃/素材检查、首页两档尺寸和关键页面错误/空态验证。涉及 S05/S06 已验功能的共享调用方时同步回归。

验收材料：双会话/四会话身份与网络核验、连续录像或截图、请求和服务端事件日志、恢复与负例、两档视口数据、build/pytest/颜色与页面门禁结果。静态占位动画或仅有手输码不算完成对应验收项。

### G2：运行时桥接、数据导入与打标（BRIDGE-10 + S10 + S11）

在隔离开发运行库与独立统计/导入库中，先验证双校区运行时读取边界和旧首页闭环，再按 S09 契约导入真实 POI、标注合成食堂与共享菜谱，最后执行可恢复、可追溯的 LLM 打标及扩容查询测试。按来源记录数量链、抽样映射、重跑幂等和数据库保护。

硬前置：全量 LLM 调用前需确认模型、密钥来源、预算上限和最大调用量；未确认时允许完成不产生付费调用的预检，但不得声称 S11 已完成。高德密钥只从本地环境变量读取，不写进聊天、源码、日志或证据包。

### G3：仿真与真实对照实验（S12 + S13）

基于 G2 已验收的数据版本，运行 200 人、60 天、每日两餐和 1,000 个四人房间仿真，再从同版输入生成两组实验结果。保留随机种子、算法调用、失败/跳过、原始行、输出 JSON 和独立复算；不得用预置曲线或重复记录补量。

### G4：管理数据闭环与实验大屏（S14 + S15 + S16 + S17）

先确认 Android/JDK/SDK/Capacitor、设备、签名与服务部署条件；完成 APK 安装联调，再形成批次 1–4 的冻结版本，最后在冻结业务版本上制作展示壳和答辩录屏。组内顺序不可颠倒，展示壳不得改动已冻结业务逻辑；任何业务修改都要重跑受影响回归并更新版本指纹。

硬前置：缺少 SDK、设备、网络或签名条件时，相关验收项标记 BLOCKED，不以 H5 构建替代真机 APK 验收。外部依赖可在其他组施工期间并行准备，但不能把未完成的设备验收记为通过。

## 组内施工与统一审查规则

1. 开始每组前读取 AGENTS、MASTER_SPEC、AGENT_MEMORY、BATCH4_PLAN、REVIEW_RULES、本计划和台账；列出组内子任务、改动文件、隔离环境、外部依赖与测试矩阵。
2. 组内可连续推进多个 S 子项。先做红灯/边界测试，再改实现；每个子项至少运行直接测试，组末运行受影响的全量测试、build、门禁和真实流程。
3. 每组保存独立证据目录 `docs/review/consolidated/G1` 至 `G5`，含 SUBMISSION、BASELINE、CHECKS、SOURCE_MANIFEST、validation、完整日志，以及适用的 browser/data 证据。每个组提交后不再覆盖其证据；后续影响已封存组时，在最终清单中标明重验范围。
4. 保留所有既有 r01/r02 与历史复审包。严禁触碰 `/admin` 以外的范围约束、演示库、S10 封存库或其他受保护库；本计划中 G4 明确授权实现 `/admin` 范围。
5. 五组完成后提交一个总清单，列出每组源码/数据指纹、测试命令、证据路径、未决项、受保护库摘要和跨组回归关系；Codex 再一次性复核源码、原始证据、独立测试、必要的浏览器/真机流程和数据。
6. 统一审查结论仍为 PASS / CHANGES_REQUIRED / BLOCKED。任一组存在未关闭 P0/P1/P2、必要外部验收缺失、证据失配或数据安全问题，总体不得 PASS；修复后重跑受影响组和跨组回归，再复审。
7. 统一审查通过前，不把 S07 或其他未验收 S 子项标为 PASS，不启动展示壳公开发布，不声称批次冻结完成。Codex 依据最终审查结果一次性更新台账和相关 REVIEW 记录。
